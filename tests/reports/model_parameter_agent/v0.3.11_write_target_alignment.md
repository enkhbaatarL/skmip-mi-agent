## Root cause and correction

`LiqUtilAdjustment` previously built selectable slots from the union of authoritative workbook rows and legacy LUT rows.
That admitted `Cove Point LNG / Cove Point LNG T1`, although the final `LiqUtilAdjustment` sheet owns the exact row
`Cove Point Export / Cove Point Export / Operational / 5.25`.

The `new-bc-v4` contract now distinguishes write targets by row policy:

- `appendable`: fixed-column targets may accept a new row after header, axis, unit, and value-semantic validation.
- `existing_exact`: matrix targets require an exact existing target row and period. Target row identifiers and metadata
  are canonical, and LUT-only keys absent from that target are blocked before slot selection.

For the current extend7 release, the six fixed-column parameters remain appendable. `LiqUtilAdjustment` is
`existing_exact`. Its 23,820 authoritative 2026–2030 source slots exactly equal its 23,820 target-backed slots.

## Recurrence guard

The parameter addition guide now requires every future parameter to declare `appendable` versus `existing_exact`,
prove source/LUT/final-target alignment independently, and add a focused test showing that every selectable slot has
the required final-target mapping. Fuzzy matching and unapproved aliases remain prohibited.
